# M2 execution acceptance coverage map

This map records what the tests establish at the execution/certification boundary. It does not
claim that the broader H1/H3/#261 requirements are complete.

| Requirement | Existing coverage | Added coverage | Remaining limit |
|---|---|---|---|
| #18: block base-fee, gas-limit and timestamp mutations are rejected before certification | `engineapi/adapter_test.go::TestAdapter_Verify_RejectsTamperedAttributes_WithoutCallingNewPayload` is skipped, so it is not passing evidence. `engineapi/adapter_v2_review_test.go` covers authenticated input derivation and attribute binding, but not the three consensus header mutations. Ureth `real_pool_payload_resolves_prefix_skips_oversized_and_replays` checks base fee as `BaseFeeDiff`; gas-limit and timestamp there are only generic error checks. | Ureth [PR #46](https://github.com/ristik/ureth/pull/46) adds isolated typed `UnicityConsensus` assertions for `BaseFeeDiff`, `GasLimitInvalidDecrease` and `TimestampIsInPast`. `TestRound_RefusesCertificationWhenSelfVerificationIsInvalid` pins the BFT boundary: a local `StatusInvalid` verdict produces no certification request. | The adapter boundary test does not launch a networked malicious leader; real-Ureth consensus rejection and the BFT no-submit test establish the local boundaries independently. |
| #20/#262: a public caller cannot advance the privileged SealRegistry clock | BFT `evmroot` tests cover skipped-round threshold behavior, not the deployed registry's public-call guard. Previous Ureth system-call tests exercised privileged execution but did not call `open` as an ordinary public caller. | Ureth [PR #46](https://github.com/ristik/ureth/pull/46) calls the pinned registry's valid next-round `open` with a non-system caller, asserts the EVM revert, and verifies the round cursor is unchanged. | This is an in-process real-EVM negative, not a process-level RPC rehearsal. |
| #261: companion data remains bound across enabled routes | `engineapi/verify_companion_test.go` and `archivewiring/restore_test.go` cover separate boundaries; they did not reuse one paid/idle/transition fixture across build, follower import and restore replay. | Ureth [PR #46](https://github.com/ristik/ureth/pull/46) captures a paid first-certified block, an idle block and an idle root-epoch acknowledgement block, reuses the exact payload/companion pairs through build, follower import and replay, exercises context/order/reorg/persistence failures, and publishes the route matrix. | Deterministic acknowledgement IDs are used in the Ureth fixture; BFT certificate authentication remains at the separate caller boundary. The bounded profile keeps shard epoch zero, so this is not shard membership handoff evidence. |

The certification gate is in `shardnode/round.go`: after self-verification, any status other than
`StatusValid`, `StatusSyncing` or `StatusAccepted` returns before `Submit`. The new round test pins
the `StatusInvalid` branch directly.
