# P85 weight quantization (bounded weighted leader lookup, Part 2)

Design: `briefs/leader-lookup.md` as amended by `briefs/leader-lookup-review.md` (F1-F3, A1, A5). Status: the pure function and its vectors are
implemented in all three places; the election, custody, root projection and ureth cap follow in the slices listed at the end.

## The rule

Raw weights `x_i = floor(principal_i / bondUnit) > 0` (ranking and collateral stay on `x`). For a committee of `n` members, `X = sum(x)`:

```
X <= B:  q = x
X >  B:  s = ceil(X / (B - n)),  q_i = max(1, floor(x_i / s))
```

`B = 65,536` is the single profile cap on the total committed weight (the constant dev3's Part 1 introduces; this work imports it, it does not
define a second one). `q` is the committed voting, leader, reward and threshold weight; thresholds are recomputed from `q`; the committed
mirrored root/EVM weights are `q`. `1 <= q_i <= x_i`, `sum(q) <= X/s + n <= B`, and the raw order is preserved weakly. K is the exact acknowledged
incumbent committee and is never re-quantized; the continuity checks compare a trial's `q` against each predecessor's committed weights.

One pure function, three evaluations, one vector file (`unicity-pos-contracts/test/p85/fixtures/quant-vectors.json`, exact integers, generated by
`tools/quant_vectors.py`): `Quantize.sol` (the election), `evmassign.Quantize` (root projection and derivation checks), `quant::quantize` (ureth).

## Security premise (F3)

BFT safety assumes the Byzantine **committed q-weight** is below one third, not the raw stake. For any member subset `S`,
`|q(S)/Q - x(S)/X| < 2n/Q` with `Q = sum(q)`; since `Q > (B+1)/2 - n` (about 32,700 at `n = 64`) a subset's share moves by less than 0.4% (fuzz
worst case 0.08%). A 64-member example: one whale plus 63 minimum bonds moves the minimum bonds' share from 6e-8 to about 0.1%. Every
"less than one third of the stake" statement elsewhere (P85 design section 1, the operator guide) is to be read as a statement about `q`.

## Rewards (A1, owner decision)

Rewards stay on the committed `q`. A member with `x < s` is paid as if it held `s` units, up to `s` times its raw share (X = 1e8 units gives
`s` of about 1,527). The aggregate distortion is under `2n/Q` of each interval budget; ranking by raw weight and `N_max <= 32` limit exploitation.
The alternative (pay on the committed raw `x`) is kept open because `x` is committed in the same record.

## Continuity at X = B / B+1 (A5)

Crossing `X = B` halves every weight (s jumps from 1 to 2). Normalized weights barely move, so the continuity distance stays under `2n/Q`; the
vectors for `X = B` and `X = B+1` are in the shared file.

## What commits `x` (F2)

`q != floor(principal/bondUnit)` once `X > B`, so the frozen identity/exposure record carries both: `rawWeight` (x) and `weight` (q), both in the
record's commitments. Coverage (`EligibilityReader.covered/stillCovered`) and `StakeCustody._checkPrimaryMember` check the principal against
`x * bondUnit`; voting, leader, reward, threshold and continuity use `q`. Root and ureth recompute `q = quant(x, n, B)` from the committed `x`.
