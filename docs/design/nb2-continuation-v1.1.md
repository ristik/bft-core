# NB2 continuation v1.1

**Final implementation specification · 21 November 2026.** A holder can return a native-asset token whose full provenance exceeds one transaction. The common path verifies and pays in one call. The recovery path verifies the same claim in bounded calls, then pays through the same vault. Axis B (long lineage) is the implementation priority. Axis A (old signed burn) must work before funding the vault. The claimant or a voluntary relayer funds execution.

## Changes from v1

- A child mint signs a 32-byte commitment to its verified parent's terminal split spend. The evidence carries root-to-leaf records and detached allocation proofs. Every ancestor is still verified. The format removes recursive signed messages, reverse discovery, traversal openings and SHA checkpoints.
- Use stock whole-message SHA-256 at 0x02 and existing B1 primitives. Drop 0x0106, its VR activation and its release ticket. Each root and child still has a certified mint transaction. **#1257 (removing mint transactions) is outside this release.**
- Use a fresh bridge profile and generation. Both ordinary and recovery verifiers, signers, wallets and vectors use this format. A testnet reset is sufficient. There is no migration or dual decoder.
- Logical reads, refusal stages, cap ownership, reference pins and vector ownership are specified below. The revised through-payout targets are 44 transactions / 390M gas for 600 transfers, 46 / 395M with one split, and 8 / 50M for the 20-split fixture. These are qualification ceilings.

## 1. Notation, profile and trust

`U` is SHA-256, `Kec` is Ethereum Keccak-256, `||` concatenates bytes. `uW` is unsigned big-endian with width W bits. Addresses are 20 bytes, hashes 32. `blob(x) = u32(len(x)) || x`. Arithmetic is checked. `C(x,…)` is the canonical CBOR array of its arguments, `b(x)` is a CBOR byte string, `tag(t,x)` is a tagged item, and literal strings in hash formulas are ASCII bytes. `A(v)` is a CBOR byte string containing the shortest positive big-endian encoding of v, 1–32 bytes. There are no alternate encodings of an amount. Define `H(label,fields…) = Kec(Kec(ASCII("UNICITY/NB2/CONT/1.1/" + label)) || fields…)`. Hash fields are raw bytes unless the formula explicitly uses CBOR.

Bridge protocol version is **10**. Flat evidence and continuation packets use `w=u16(0x0101)`. Γ is the following 19-field canonical array. The verifier derives D from exact Γ. The vault checks the expected network, deployment, asset derivations, profile digest, ordinary verifier and runtime, and its own address and chain ID.

```text
Γ = C(b("UNICITY_NB2_CFG"), 2, network, b(rootGenesis), b(executionGenesis), chainId,
      evmPartition, b(evmShard), aggPartition, b(vault), b(asset), b(ty), b(aid),
      b(profileHash), b(ordinaryVerifier), b(ordinaryRuntimeHash), K, B, A(Qmax))
D = U(Γ)
stem = decimal(network) + ":" + hex(rootGenesis) + ":" + hex(executionGenesis) + ":" + decimal(chainId)
ty = U("unicity-bridge:unicity-native-nb2-11:" || ASCII(stem))
aid = U("unicity-bridge-coin:unicity-native-nb2-11:" || ASCII(stem))
asset = U("unicity-nb2-asset:native-uct")
```

Use lowercase unprefixed hex and minimal decimal. Network is a positive u16, chain ID a positive u64, the two partitions distinct positive u32s. Root genesis pins the UTB genesis EntryID. The canonical native shard ID has 1–33 bytes, a terminal delimiter bit and at most 256 prefix bits. Production uses K=64 payments per segment, B=16 buckets and Qmax ≤2^144−1. The profile hash commits to the released semantic profile bytes. The authenticated deployment binds the two genesis identities, EVM partition/shard and continuous execution history to the vault. Trust assumptions are certified EVM execution, authenticated historical root committees, certified single spending by the configured aggregation partition, cryptographic binding and a wallet that protects its deposit secret. Availability assumptions appear in §§6–8.

## 2. Flat provenance and the signed parent link

Transactions and proofs use canonical definite-length CBOR. Use shortest heads, exact arities, numeric ranges, full consumption, no indefinite items or duplicate keys. Each length-framed mint, proof, pair and allocation below is one decoding unit at depth zero. A byte string interpreted as CBOR (reason, value data, return data) starts a new unit. For an array, map or tag at depth d require d+1≤16, including empty containers. Decode its children at d+1. Text and maps are admitted only where the canonical native certificate format requires them. Native UC shape, decode/re-encode and resource checks also apply. A packet or page boundary never resets a unit's depth.

```text
E       = ASCII("NB2L") || w || u64(levelCount) || level[0] || … || level[levelCount−1]
level   = blob(allocation) || blob(M) || blob(proofM) || u64(transferCount) || entry[0] || …
entry   = blob(C(T, proofT))                // exactly transferCount entries in the level
M       = tag(39041, [2, network, Pnext, b(salt32), b(ty), b(reason), b(data), deadline])
T       = tag(39045, [2, Pnext, b(mask32), dataOrNull, deadline])
P       = tag(39032, [1, b(code1), b(params)])
CD      = tag(39031, [2, Psource, b(sourceHash), b(txHash), deadline, b(unlock65)])
proof   = tag(39033, [1, CD, t, b(nativeBitmap32 || siblings), UC])
data    = tag(39050, [1, [[b(aid), A(value)]], null])
```

Numeric suffixes in the grammar denote byte widths. The proof time t is u64. A deadline is either null or a positive u64. For transfers, dataOrNull is null or a CBOR byte string containing the exact split manifest or return data. Mint recipients and continuing holders are signature predicates (code byte 01, compressed secp256k1 point33). Burn predicates use code byte 02 and the 32-byte reason hash. A redemption has at least one level and at least one transfer in every level. The last transfer of every nonfinal level spends that level into a split. The last transfer of the last level spends it into the return. Require complete consumption of E. In **held** mode every ancestor still ends in a certified split. The last level must end at its signature-owned mint with zero transfers, or at a continuing transfer with a signature owner and null data. Held verification returns that spendable state. Only a verified terminal return burn produces a payout verdict or completion event.

**Root.** Root allocation has length zero. Its reason is `tag(39051,[1,b(D),n,b(r),DepositProof])`. Under the shared vault guard, `deposit(bytes firstOwner,bytes32 rho)` requires a valid signature predicate, positive native value, space in the 56-bit nonce n and room in Qmax. It increments n (first deposit is one), credits the 144-bit liability Q, and emits `Deposited(uint64 indexed nonce,bytes32 domain,uint256 amount,bytes32 rho,bytes firstOwner)`. Verify the successful certified log per §5, exact indexed nonce and canonical ABI including its 42-byte first-owner predicate, equal D and positive amount. Require `rho=Kec(Kec("UNICITY_NB2_DEPOSIT_SECRET")||D||r)`, `salt=U(C(b("UNICITY_NB2_DEPOSIT_SALT"),b(D),n,b(r)))`, r exactly 32 bytes, and exact equality of mint first owner, value data, network and type to the funded claim. Use an unused secret from the wallet's backed-up deposit-intent journal. A value transfer outside deposit increases no liability.

**Child.** Nonroot allocation is the complete canonical CBOR array of allocation steps (a zero-step proof encodes as byte 80 hex). The child reason is exactly `tag(39044,[2,b(parentLink)])`. Compute these values during verification:

```text
tokenID    = U(C(b(salt32),network))
manifest   = tag(39046,[b(manifestRoot32)])
parentLink = U("UNICITY/NB2/1.1/PARENT" || D || parentID || splitSID ||
               splitTxHash || manifestRoot32 || u256(parentAmount))
output     = U(C(b("UNICITY_NB2_11_OUTPUT"),b(parentID),network,b(exact Pnext),
                 b(salt32),b(tokenID),b(ty),b(exact mint data),deadline))
```

The parent signs and certifies the terminal transfer containing `b(exact manifest)` and a burn predicate on `U(exact manifest)`. Derive splitSID and splitTxHash from that verified transfer. Only the immediately following level may consume the resulting parentLink. Check equality to the child's signed reason. Verify a membership-and-sum proof for key tokenID, commitment output and the child's positive amount against that parent's manifest root and **exact full amount**. Leaf is `U(0x10||key||output||u256(value))`. For each leaf-first step `[depth,b(siblingHash),A(siblingSum)]` (strictly decreasing depths 255…0), use bit depth of the key counted MSB first. Bit zero places the running pair on the left. Hash `U(0x11||u8(depth)||leftHash||u256(leftSum)||rightHash||u256(rightSum))` and add sums without u256 overflow. Check final root and sum. No other parent lookup is permitted.

**Construction order matters.** Choose each child's salt, owner, asset/value, type and deadline. Sort distinct child IDs lexicographically. A singleton is its leaf. For two or more IDs branch at their first differing bit, partition into zero/one subsets and recursively hash their resulting pairs at that depth. Sign/certify the parent split burn, derive parentLink, then build/sign/certify each child mint. The output commitment excludes the child justification, so the parent can commit all allocation fields before its own burn hash exists. The child carries no ancestor bytes. Its proof transport may change across providers while its exact signed mint stays fixed. A recipient receives the complete ancestor records and its own allocation path. A digest by itself cannot validate a held part.

**Certification of every source.** Hash the exact complete signed M or T with U. For a mint, `h0=U(C(b(tokenID),b(U("TOKENID"))))`. The source signature key is the compressed public key of the scalar `U(C(b("I_AM_UNIVERSAL_MINTER_FOR_"),b(tokenID)))` in [1,nCurve−1], without reduction. For a mint require the source predicate on that key and source hash h0. For a transfer use the preceding authenticated owner and state. Require CD's source predicate, source hash, tx hash and nullable deadline to match. Verify the 65-byte unlock r32||s32||recoveryID against `U(C(b(sourceHash),b(txHash)))`. Require 1≤r<nCurve, 1≤s≤floor(nCurve/2), ID 0 or 1, recovery to the actual source key and a valid secp256k1 signature. Require t<deadline if present. Derive `sid=U(C(Psource,b(sourceHash)))`, require it unused over the **entire** lineage, and prove the native leaf `U(C(b(txHash),t))` at sid (§5). The resulting owner is Pnext and resulting state is `U(C(b(0x0000||sourceHash),b(mask)))`, using tokenID as the mint mask. A continuing transfer requires null data and a signature recipient. Every root and child mint consumes a certified source.

**Terminal verdict.** Require return data `R=tag(39052,[1,b(D),b(asset),b(recipient20),A(value),a])`, a burn predicate on `U(exact R)`, the whole part's value and `0≤a<2^48`. Recipient is nonzero and differs from the vault. Compute `btid=U(C(b("UNICITY_NB2_BURN"),b(sid),b(txHash)))`, `eta=U(C(b("UNICITY_NB2_REDEMPTION"),b(D),b(btid)))`. Both verifiers derive exactly `V=(D,eta,a,asset,recipient,value)`. The source set includes this final burn. A different evidence commitment, submitter or valid certificate presentation for the same burn cannot change its eta.

## 3. One ordinary relation, two ways to execute it

The ordinary verifier accepts `verifyReturn(bytes gamma,bytes evidence)` and returns V as six canonical ABI words or reverts. It reads E in order with in-memory sets for SIDs and claim consistency. The recovery verifier runs the same checks on position-authenticated evidence and supplies authenticated set openings. A certified completion implies ordinary acceptance on the same E under the same historical authorities, ignoring the ordinary transaction envelope. For every ordinary-valid E in the published recovery envelope, available witnesses, funding and inclusion must permit a partition into bounded operations. Every legal partition that completes must derive the identical V. A packet cut can change fee, latency or the first diagnosed error.

**Pins.** Record native semantics, prices, registry layout and execution release as exact opaque bytes authenticated by the release manifest. With §1 H, define `release=H("RELEASE",U(certDescriptor),U(memberDescriptor),U(registryLayout),U(executionDescriptor),U(buildIndex),U(primitiveVectors))`. The execution descriptor covers the active Cancun/B1 rules including standard SHA-256. The build index identifies native execution binaries by digest. The primitive vector artifact is independent of deployment sessions. Production uses actual authorized artifact bytes. No new VT-07 rule or fork is required.

`P=H("PINS",release,u16(count),records…)`. A record is `u16(role)||addr20||digest32`, in increasing role order. Roles 1…5 are ordinary verifier, receipt verifier, B1 certificate at 0x0100, B1 membership at 0x0102 and seal registry. Normal contract digests are runtime code hashes, native digests are U of the respective descriptor, and registry digest is `H("REGISTRY",runtimeHash,U(registryLayout))`. Include any additional transitive custom helper exactly once, roles 256 upward in raw address order. `G=H("GEN",freshSalt32,D)`. For N=len(E), page root Rpage:

```text
S = H("SESSION",w,G,D,vault20,recovery20,recoveryRuntimeHash,P,u64(N),Rpage)
```

Allocate deployment addresses before constructors run. The ordinary verifier checks the supplied Γ and uses its own runtime identity without embedding its eventual D. The vault supplies its fixed Γ. The vault pins the recovery address, expected runtime and dependency graph. The recovery verifier pins Γ and its helpers. The authenticated manifest independently pins the final vault runtime, deployment blocks, genesis bindings, compiler, optimizer, EVM target, constructor arguments, reproducible binaries, limits and historical authority sources. Native identity requires the authenticated chain rules as well as an address. The release must sustain the pinned B1 behavior, usable pricing and historical registry for the lifetime of the funded generation. Refuse mismatched pins, test builds on production and reset chains. No upgrade key, proxy, caller-selectable verifier or per-session vault slot.

**Pages.** Require 14≤N≤2^64−1. Each 4,096-byte page i has leaf `H("PAGE",u64(N),u64(i),u16(len(data)),data)`. The last page contains exactly its remaining bytes. Pad leaves to a power of two with `H("PAD")`. Ordered parents are `H("PAGE_NODE",left,right)`. A proof has exactly ceil(log2(ceil(N/4096))) siblings (≤52), bottom up, low index bit first, bit zero puts the running node on the left. A one-page proof has none. Check canonical default hashes for wholly padded siblings. Check additions, ranges and indices before computing offset or allocating.

**Entry and packet.** Recovery exposes nonpayable `run(bytes)`, `advanceGaps(bytes)`. The vault exposes nonpayable `redeemRecovered(bytes)`. Each argument uses canonical Solidity ABI: correct selector, offset 32, exact dynamic length, zero padding and no trailing bytes. All three packed arguments begin `w||u64(N)||Rpage`. For run append, in order:

1. `u8(mode)`: 0 Start has no predecessor fields. 1 Resume adds the exact 290-byte state and `blob(DepositProof)` for the preceding Progress.
2. `u8(pageCount)` (1…32), then each `u64(index)||pageData||siblings` with computed lengths and strictly increasing indices. Verify every submitted page against Rpage.
3. `u8(opCount)` (1…16), then each `u8(opcode)||sidOpening||claimOpenings`. Opcodes 1 RootMint, 2 ChildMint, 3 Transfer each consume exactly one certified source. RootMint carries two claim openings in deposit-then-mint order, the others one. The SID opening is transmitted first for every operation. Openings are specified in §4. Consume every byte. A known opcode must match phase. Only the last record may complete.

**State opening.** The packed fields are `phase:u8, seq:u64, pos:u64, levelsLeft:u64, transfersLeft:u64, seenRoot:32, claimRoot:32, owner:33, state:32, tokenID:32, amount:u256, parentLink:32, parentManifest:32`. `digest=H("STATE",S,stateBytes)`. Start authenticates the 14-byte prelude, requires levelCount>0, and initializes phase=1, pos=14, levelsLeft=levelCount, both roots to their prescribed empty roots, other fields zero. levelsLeft includes the active level. The owner field stores the compressed signature key. Store numeric fields big-endian and zero every reserved or inactive field as prescribed. All updates below use authenticated reads and checked counters.

| Operation | Exact logical reads and successor |
|---|---|
| RootMint / ChildMint | At pos read the entire level header through transferCount: three length prefixes and their payloads, then eight count bytes. Enforce the expected allocation/reason kind, perform §2 root or parent/allocation checks, verify the mint and insert its SID. Require transferCount>0. Set owner, state, tokenID and amount from the mint result, zero parentLink/parentManifest, set transfersLeft to count, pos to the next byte, phase=3. |
| Transfer | At pos read exactly one length-prefixed pair, verify it, insert the SID, advance pos and decrement transfersLeft. If more transfers remain, update owner/state. On the last transfer with levelsLeft>1 verify the split burn, compute parentLink and save its manifest root, retain the parent tokenID and amount, zero owner/state, decrement levelsLeft and enter phase 2. With levelsLeft=1 verify the return burn, require pos=N and all obligations discharged, and emit Complete. |

The supplied page indices must equal the union of pages intersecting these reads, including the prelude only on Start. No scan of future transfers, other levels or speculative prefetch contributes a page. A cached read still counts. There is no separate discovery, unwind or hash operation. Validity of all lengths does not grant permission to skip content.

Increment seq once per successful packet, before forming its output, starting at 1. Events are non-anonymous, have exactly two topics (Keccak of the standard event signature and indexed S), and exact canonical ABI data (2, 7 or 9 words). A successful recovery call emits exactly one event of the appropriate kind:

```solidity
event NB2Progress11(bytes32 indexed session,uint64 seq,bytes32 stateDigest);
event NB2Complete11(bytes32 indexed session,uint64 seq,bytes32 domain,bytes32 eta,
                    uint64 minSegment,bytes32 asset,address recipient,uint256 amount);
event NB2Gap11(bytes32 indexed session,uint64 seq,bytes32 domain,bytes32 eta,
               uint64 minSegment,bytes32 asset,address recipient,uint256 amount,
               uint64 nextSegment,bytes32 head);
```

Resume authenticates one successful Progress receipt from the pinned verifier for exactly (S,opened seq,opened digest). A second independently certified copy of that state is interchangeable. Anyone may continue or branch from it. Every successor verifies its own predecessor, so a final call needs one event proof. A phase, sequence number, RPC log or held-prefix checkpoint alone grants no authority.

## 4. Source and certificate consistency across packets

The ordinary verifier keeps two maps in call memory. The recovery verifier commits their contents using separate depth-256 sparse binary trees. An empty leaf is 32 zero bytes. Internal nodes are `H("SID_NODE",left,right)` or `H("CLAIM_NODE",left,right)`. Compute each default parent from two child defaults. A sparse opening is `bitmap32||sibling32…` in ascending tree height. Bit i in the big-endian bitmap, counting from its least significant bit, means one explicit nondefault sibling at height i. Require exactly popcount siblings, reject explicit defaults, and orient each fold by bit i of the big-endian key (zero places the running node left). Verify the old root before installing the new one.

- **Source set.** Prove the §2 SID vacant, then insert `H("SID",sid)`. Keep the root across every level, epoch and transaction. No duplicated source can produce Complete.
- **Claim map.** For each token UC, including the deposit UC, form the exact B1 claim bytes `u32(partition)||u16(shardLen)||shard||shardConfigHash||stateRoot||irHash||blob(canonicalUC)`, where irHash is U of native InputRecord.Bytes(). Key is `H("CLAIM_KEY",U(completeCanonicalSeal),u32(partition),u16(shardLen),shard)`. Value is `H("CLAIM_VALUE",U(claimBytes))`. Leaf is `H("CLAIM",key,value)`. First use of a key in a packet carries `u8(0)||u8(present)||[oldValue32 if present]||sparseOpening`, present exactly 0 or 1. Prove absence and insert, or prove presence and require equality. A later use of that key in the same packet must use exactly `u8(1)` and match its established value. The cache resets per packet. Different full seals, including valid alternative signature subsets, have different keys. Every occurrence still binds its own shard and membership.
- **Native batches.** Validate each distinct packed claim in the current packet through CERT_BATCH_V2. Coalesce exact duplicates within the call. Split batches to meet native caps (16 claims, 262,144 bytes and all scanner, path, signature and token budgets). A semantically false batch rejects, even if diagnostic singletons succeed. The claim map carries the conflict rule across cuts. It grants no certificate authority. The predecessor receipt uses a separate authenticated transport claim outside the lineage maps. Flush all pending checks before emitting. Require native success and exactly the prescribed two ABI words (version 2 or 1 respectively, canonical true).

## 5. Historical authority, receipt acquisition and failure order

Use the pinned network and authenticated UTB history for each UC's own seal epoch. Check canonical native encoding/re-encoding, partition/shard binding, InputRecord, TRHash and actual ShardConfHash in the shard fold, full unicity path to the seal, authenticated usable epoch, inclusive start/exclusive successor start when closed, root round ≤ authenticated origin and weighted seal quorum floor(2W/3)+1. Only valid canonical signatures of members contribute their weight. Never choose a tip supplied by the claimant. Refresh unavailable UTB history from genesis or a trusted checkpoint with authenticated successors. On chain use the permanent, journal-aware B1 registry. For each aggregator occurrence verify the SID belongs to its certified shard, `t≤IR.timestamp` and native RSMT_MEMBER_V1 at its certified state root, with exact SID and leaf value. Native path is bitmap32 plus one hash for each set bit in native root-to-leaf order, at most 256. Apply the native per-object/aggregate caps. [B1 contract and oracle](https://github.com/ristik/bft-core/tree/206cfcf91/b1ref)

**Receipt proof.** Use canonical CBOR `DepositProof=[1,b(evmUC),b(headerRLP),txIndex,logIndex,[b(nodeRLP)…]]` for deposit, seal, Progress, Complete and Gap. Authenticate the configured EVM partition/shard. Require UC.IR.blockHash=Kec(headerRLP) and UC.IR.hash=header.stateRoot. Use canonical Cancun 20-field execution headers through parentBeaconBlockRoot, minimal integers, fixed-width fields, empty ommers, difficulty zero, empty withdrawals root, nonzero u64 base fee, zero blob gas and excess, number <2^63 and extraData ≤32 bytes. Prove the receipt under header.receiptsRoot at RLP(txIndex), canonical MPT nodes/references, full key, no unused/duplicate node. Accept successful legacy or typed (01/02/03) receipts only. Select logIndex **within the receipt**. Require exact emitter, topic count/signature, indices, field widths and ABI data. For recovery logs check S and nonzero seq. Data must match the opening wherever supplied.

For a transaction mined in block h, fetch its canonical child h+1 and require its parent hash is hash(h). Obtain `unicity_getSealCompanionV1(hash(h+1))` with the certificate and technical record. Witness zero must certify h's block hash and state root. The child wait is followed by actual certificate publication and retrieval. Retain block bodies/headers, receipts, logs, companions, UTB and release data for the vault lifetime. Retry an unpublished or unknown child. For pruned evidence use an independent archive or a saved authenticated proof. Rebuild the receipt trie. Inconsistent providers, incomplete receipts or missing authority confer no progress.

**run refusals.** Apply (1) packet framing, selectors/version, byte/count bounds, valid modes, opcode grammar and exact consumption → `BadPacket()`, (2) receipt, chosen state, context and predecessor digest → `BadPredecessor()`, (3) page table order, paths and required coverage → `BadPage()`, (4) operations in order, including known opcode/phase mismatch, out-of-frame span, evidence grammar, source/claim openings, cap or semantic failure, and any record after Complete → `BadStep()`. Detect missing pages when an otherwise in-range read needs them. Check unused pages after all operations and before emission. Start consumes the prelude as its first evidence read. Counter overflow refuses the step. Malformed packet framing and an invalid authenticated evidence item are distinct. A failed packet emits nothing, leaves the prior receipt reusable, and cannot credit earlier operations in that packet. A missing native host, malformed return or OOG fails closed. The one-call verifier uses the same acceptance relation, including cross-claim conflicts, with ordinary ABI rejection. For multiple faults, the first error can differ between the ordinary and recovery routes.

## 6. Payment, recent buffers and recovery of an old burn

Both payout routes use the same (D,eta,a,asset,recipient,value), transient reentrancy guard, liability Q, and physical recent buffers. Native value moves only to the signed recipient. The ordinary route is `redeem(bytes evidence,bytes32 claimedEta,uint64 claimedStart,bytes history)`. History is empty or an unsigned 32-byte start head followed by a nonempty integral number of gap proofs. Apply the guard, check history length and current/previous endpoint eligibility, fold any history for the claimed eta to the stored head, then scan the live buffers for replay. Next verify E with the pinned ordinary verifier, require the claimed eta and a to equal the fields of V, validate V and complete the payment atomically. Each scan runs once. The normal route performs no recovery lookups, writes or receipt checks beyond ordinary evidence.

**Archive.** Sort each sealed segment's K paid IDs as unsigned 256-bit integers. For adjacent IDs l,u including the wraparound pair, leaf = Kec(00 hex || l || u), ordered internal node = Kec(01 hex || left || right). Gap proof is `u8(i)||l||u||siblings` with log2(K) 32-byte siblings, leaf up. At height h use bit h of index i, least significant bit first. Zero puts the running node on the left. Require i<K. For i<K−1 require l<eta<u. For i=K−1 require l>u and (eta>l or eta<u). Derive segment root M from that proof. Let `h0=Kec(Kec("UNICITY_NB2_ARCHIVE_GENESIS")||D||u16(K))` and `h[j+1]=Kec(Kec("UNICITY_NB2_ARCHIVE_STEP")||D||u64(j)||h[j]||M)`. Genesis has c=0 and no previous endpoint. Wallets choose a=j+1 from a verified vault `SegmentSealed(j,…)`, or a=0 with genesis head. A reported state height alone cannot authorize a future signed start.

**Cold packet.** Append to the common §3 header `u8(kind)||blob(receipt)||u16(gapCount)||optionalStartHead||gapBytes`. Kind 1 means Complete, kind 2 Gap. Include the 32-byte start head **only** for kind 1 with positive gapCount. Require exactly gapCount consecutive proofs. From Complete begin at signed a. From Gap use the certified next index t and head, with a≤t<2^48. Obtain V from the certified event. A wrong unsigned starting head may produce another prefix, but cannot pay against a different stored endpoint.

| Stage | advanceGaps | redeemRecovered |
|---|---|---|
| Entry | Accept 1…1024 gaps. | Enter shared vault guard (`Reentrancy()`). Accept 0…1024 gaps. |
| Decode/authenticate | Both calls reject framing, proof blob length, count, optional head or suffix length with `BadPacket()`. A false receipt, wrong event kind, emitter, session, malformed event or invalid certified cursor is `BadPredecessor()`. | Same. |
| Endpoint and fold | Compute e=start+count in the NB2 48-bit range and seq+1 in u64, otherwise `BadStep()`. Verify each strict gap for eta. Emit only Gap(S,seq+1,V,e,resultingHead). | Reject a>c with `FutureIndex(a,c)`. Check e in range (`BadStep()`), then e=c or c>0 and e=c−1 (`StaleEndpoint(e,c)`). Fold the suffix. |
| After fold | Either call rejects a non-excluding/bad proof with `BadGapProof(i)`, i zero-based within this call. Advance has no custody effects. | Compare to stored h[e] for any positive fold **and every Gap receipt, including zero suffix** (`ChainMismatch()`). Only a fresh Complete with zero suffix and a=e is headless. Then settle. |

**Shared settlement.** Scan the current buffer (m entries), and also the full previous buffer when e=c−1. Use high log2(B) bits as bucket tag and reject equal live eta (`AlreadyPaid(eta)`). Require D, native asset, any claimed fields, nonzero recipient different from vault, positive amount and sufficient Q (`DomainMismatch`, `AssetMismatch`, `ClaimMismatch`, `BadRecipient`, `ZeroAmount`, `LiabilityUnderflow(Q,amount)` respectively). Insert eta in current position m, update its tag, debit Q, emit `Paid(bytes32 indexed eta,address indexed recipient,uint256 amount)`. If this fills K slots, check that c can advance (`SegmentCounterExhausted()` on exhaustion), check that sorted IDs strictly increase, compute M and the new head, emit `SegmentSealed(uint64 indexed segment,bytes32 headBefore,bytes32 headAfter,bytes ids)` with exact concatenated sorted IDs. Rotate current to previous, increment c, set m=0. Ignore stale cells outside live populations. Preserve deposit nonce. Pay with an ordinary native-value call to the signed address. Payout failure reverts all effects/logs, including the seal. A reentrant inner vault call reverts with `Reentrancy()`. If the recipient catches it, the outer call can pay once. If it propagates, the outer call reverts with `PayoutFailed()`. Only ordinary redeem and redeemRecovered call this routine.

The first payment could occur only at a segment j≥a because settlement checked a≤c. On a second attempt, j must lie in the strict verified interval [a,e) or a scanned live buffer. The former excludes eta and the latter detects equality. This covers races between sessions or routes, including eviction from both buffers. Conservation across different burns follows from a funded root, certified spends, exact allocation sums and full terminal burn. The #1258 bounded model covers these abstract settlement properties and rollback. Concrete certification, calldata limits and liveness under continued sealing require the release tests. 5. **Live qualification.** Exercise late restart with a large consumed set and the preferred archive disabled. Unbounded archive loss, an always-reverting recipient and permanent non-inclusion preclude unconditional payment. ## v1.1 clarifications

**1. §§3 and 5 — A page index that prevents framing.** Return `BadPacket()` during framing if a supplied page index is outside the evidence. With a valid N, there are `1 + (N − 1) div 4096` data pages (integer division), numbered from zero. Check the index against that count before multiplying it by 4096. An out-of-range index has no defined payload length, even if it names a padding leaf in the Merkle tree. Stop at that index. The result is `BadPacket()` even if the Resume receipt would fail authentication or the bytes after the index look like a malformed suffix. A truncated index or an in-range entry with too few bytes for its computed width also fails framing.

When every entry boundary can be determined, finish framing the entire packet first. A malformed operation suffix gives `BadPacket()`. Once framing succeeds, a bad predecessor gives `BadPredecessor()` before any page authentication. With a valid predecessor (or on Start), duplicate or unordered in-range indices and invalid Merkle paths give `BadPage()`. Missing and unused pages follow the §5 coverage checks. For example, at N=4097 index 1 has a one-byte payload and index 2 fails framing.

**2. §§3, 4 and 9 — The final operation in a Complete vector.** Publish the terminal packet with the final Transfer’s SID opening and claim opening in the §4 form required for that occurrence, together with its certified `NB2Complete11` event. Include the exact topics and data for S, the incremented packet seq and all six fields of V. A Resume transcript also includes its incoming Progress state, roots and predecessor proof as usual. The final burn must pass the SID vacancy and insertion check, claim consistency and all pending native checks before emission.

The §9 requirement for successor state bytes and roots applies when the packet emits Progress. Complete has no successor state opening or state digest. Omit those successor fields from the terminal vector. The corpus requires no terminal scratch root. An implementation may log its computed roots for debugging, but consumers compare the certified Complete event as the terminal output.
